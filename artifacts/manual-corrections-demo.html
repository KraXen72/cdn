Apply the original correction

The human edits the normalized sidewalk geometry. The editor converts that edit into semantic operations: remove the red area, add the green area.

What is persisted? Intent + geometry masks + source IDs/version + expected local state.

Replay logic

state = normalized_source
state = state.difference(remove_area)
state = state.union(add_area)
Why this is safe No newer source exists yet; this is the state the operation was authored against.

Replay cases: automate the common path, review the risky one

A new BGT release is not automatically a conflict. Manual review is reserved for relevant changes.

Unchanged source

The same source geometry is still present.

→ SAFE: replay
Changed elsewhere

BGT changed, but its source delta does not overlap the operation footprint.

→ SAFE: replay
BGT fixed it too

The latest source already satisfies the human correction.

→ ALREADY_SATISFIED
Same area changed

Upstream and the manual operation changed overlapping physical space.

→ CONFLICT: review
Split / merge / missing ID

Initial version does not guess. Advanced conflation is deferred until needed.

→ REVIEW
Spatial three-way check 
source_delta = expected_before.symmetric_difference(current_before)

if source_delta.buffer(tol).intersects(operation.geometry.buffer(tol)):
    return CONFLICT
Conflict UX for nontechnical operators

Do not expose Git terminology. Show an overlay of the newer BGT change and the existing correction, then offer domain actions such as:

Keep correction Use new BGT Edit correction Re-anchor
Deliberately not promised yet: automatic arbitrary split/merge matching, persistent identity across all conflation cases, and “nearest feature wins”.

Editor path: use mature GIS now, keep the correction model editor-agnostic

The correction API/model is the product boundary. QGIS and a future web editor are clients of the same model.

debugging baseline

Raw QGIS

  • Immediate, no custom UI work.
  • Excellent layer inspection and geometry tools.
  • Too much freedom for long-term nontechnical operators.
recommended near-term

QGIS + thin Scenwise plugin

  • Select/edit normal geometry.
  • Plugin derives semantic operations.
  • Refresh corrected view directly.
  • No normal export → edit → import loop.
later

Dedicated web editor

  • Better UX for municipality/nontechnical users.
  • Large context rendered as vector tiles.
  • Only selected/local geometry becomes editable.
  • Python/PostGIS keeps geometry/replay logic.

Good demo milestone

One real-ish sidewalk edit survives an unrelated simulated BGT update automatically, while an overlapping source change produces a visible conflict instead of silently applying.

Not required to prove the architecture

PostGIS production schema, national-scale ingestion, complete plugin UX, automatic split/merge conflation, or the final web editor.

Operation record: enough context to explain and replay

@dataclass(frozen=True)
class ManualOperation:
    operation_id: str
    transaction_id: str
    sequence: int
    kind: OperationKind

    geometry: BaseGeometry | None
    attributes: dict[str, object]

    source_feature_ids: tuple[str, ...]
    source_version: str | None
    relative_level: int

    expected_before: BaseGeometry | None
    reason: str | None

Exact fields can evolve. The important part is preserving intent, provenance and the local state the edit was based on.

One sentence to anchor the demo

Humans author semantic corrections. Spatial three-way comparison is an automatic safety check used to decide whether those corrections can still be replayed after source data changes.
The system should require human attention only when the source changed the same real-world area, or when the correction can no longer be anchored confidently.
