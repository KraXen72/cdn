Scenwise DWN edit stage v2 · post-generation overlay
Architecture exploration

One patch layer between generated and published DWN

  • The generator produces an immutable baseline DWN.
  • Reviewers save corrections as patches.
  • The published DWN is a routing graph with real spatial geometry attached.
  • Patches change the effective DWN without changing the generated baseline.
  • Temporary and permanent corrections use the same patch system.

    Patch operations
    
      
    The primitives describe reviewer intent at path level. A target may be a whole path or only a selected span; the patch engine handles graph splits, cleanup, and reconnection locally.
    

      
    
        
    
          ADD_PATH
          Add a missing routable path
          
      
            
    • Stores the new LineString plus how its endpoints should connect to the existing network.
      • 
            
    • Used for missing crossings, entrances, links, and other path geometry.
      • 
            
    • The engine inserts or reuses graph nodes and splits touched edges where needed.
      • 
          
    
        
    
        
    
          SUPPRESS_PATH
          Remove a generated path or selected span
          
      
            
    • Targets an existing generated path, optionally only between two positions on it.
      • 
            
    • The selected span stops contributing routable geometry to the effective DWN.
      • 
            
    • Unused nodes are removed and unnecessary degree-2 nodes can be collapsed.
      • 
          
    
        
    
        
    
          REPLACE_PATH
          Correct path geometry as one edit
          
      
            
    • Targets an existing path or span and supplies its corrected replacement line.
      • 
            
    • Unchanged attributes can be carried across instead of being re-authored.
      • 
            
    • The engine checks that the replacement reconnects to the surrounding network.
      • 
          
    
        
    
        
    
          SET_ATTRIBUTES
          Change properties on a path or span
          
      
            
    • Overrides access, surface, width, tactile paving, kerb data, and similar routing attributes.
      • 
            
    • Temporary closure: set access=false on the selected span and give the patch an expiry.
      • 
          
    
        
    
      
    

      
    Shared target: a path-span selector. For partial edits, store the original path reference, two positions along that path, and geographic anchors near those positions. The positions say which span was selected; the anchors help resolve it safely after regeneration. If the target cannot be matched confidently, emit a QA finding instead of attaching the patch to a nearby path.
    

      
    No REMOVE primitive for now. To retire content introduced by an ADD_PATH patch, disable, expire, or supersede that patch. Add a separate removal primitive only if a concrete undo/history use case requires it.
    

      
    
        
    
          Geometry and graph stay together
          
      
            
    • The reviewer edits a path or selected span on the map.
      • 
            
    • The engine resolves that selector and splits the effective graph at span boundaries when needed.
      • 
            
    • Those split edges are implementation details, not extra manual patch operations.
      • 
            
    • Geometry correction is one REPLACE_PATH, rather than a manually coordinated suppress + add pair.
      •

    Applying a patch after regeneration
    
      
    Resolve the same local DWN region and, for span-targeted operations, resolve the stored path/span selector against it. Then check these states in order.
    

      
    
        
    
          1
          
    Region matches desired_afterThe correction is already present.
    
          NO-OP
        
    
        
    else →
    
        
    
          2
          
    Region matches expected_beforeThe old correction still applies.
    
          APPLY PATCH
        
    
        
    else →
    
        
    
          3
          
    Neither state matchesDo not guess or force the patch.
    
          QA FINDING
        
    
      
    

      
    Match means equivalent for this patch under its geometry and attribute comparison rules. It does not require byte-identical serialization. A path/span selector must also resolve confidently from its path reference, along-path positions, and geographic anchors; otherwise the result is a QA finding.

    V2 keeps the same cross-generation behavior, but applies corrections to the generated DWN instead of to source data.

    Source or generator already fixed itThe local DWN now matches desired_after.

    NO-OPPatch stays as history or can be retired.

    The DWN is a spatial graph
    
      
    Routing uses a simple node/edge graph. The graph still keeps enough geometry to line up with the real pedestrian network on a map.
    

      
    
        
    
          
        
    

        
    
          
    NodesGeographic routing points: junctions, entries/exits, crossings, or other meaningful split points.
    
          
    EdgesConnect nodes for routing and retain their real spatial geometry. A curve does not need extra routing nodes.
    
          
    Polygon geometryKeep actual sidewalk/area geometry when we have it. Local graph generation derives the routable structure from it.
    
          
    Graph cleanupSpan edits split the effective edge at their boundaries when needed. SUPPRESS_PATH removes the selected part; REPLACE_PATH inserts the corrected geometry and reconnects it locally.
    
        
    
      
    

      
    Result: routing works on a compact graph, while the DWN can still be drawn over OSM or imagery without replacing real geometry with straight routing shortcuts.
